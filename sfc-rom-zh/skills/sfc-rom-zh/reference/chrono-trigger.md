# Chrono Trigger（日版）—— 答案後來長這樣

一個「答案長什麼樣」的實例。**這裡的位址沒有一個適用於其他 ROM。**
讀它是為了看「什麼樣的東西會是真的」，不是為了拿數值。

## 字模

12x12、2bpp、分成兩塊：block A 存左邊 8 欄（每字 24 位元組），
block B 存右邊 4 欄，兩個字擠在一個 24 位元組的記錄裡。

一開始誤判成 8x12，導致某個候選字型看起來不能用；
後來反組譯 `$C25D88` 的字模取用程式才修正。

原版 704 格。改成 ExHiROM 並 patch 字模位址計算改讀分頁字模資料後，提升到 5,056 格。

## 編碼

- `0x40`–`0xFF` 第 0 頁，一位元組
- `01 xx` / `02 xx` 第 1–2 頁，兩位元組
- `03 pp cc` 第 3 頁以上，三位元組 —— **這是本專案自己加的跳脫碼**，
  patch 進對白引擎的跳轉表。**選單渲染器沒有這個東西。**
- `0x21`–`0x3F` 一位元組字典參照，`12 xx` 兩位元組
- `0x00` 終止；字典條目的長度前綴是**字元數**，不是位元組數

## 位元組預算

字串位址 = 16-bit 指標表條目 + **指標表所在的 bank**：
`$C25800` 就是 `LDA $0F / STA $33`。

把那一條指令換成重映射，十五個腳本區段各自拿到一個 64 KB 的 bank，
而每一張指標表都留在原地——這點很關鍵，因為那些表是被散在六個銀行事件資料裡的
24-bit 指標指到的，而且**沒有主表**。

## 兩套文字系統

對白用 12x12 字模和 patch 過的解碼器。
選單的說明列也用 12x12，但道具／技能／怪物名、取名格子、選單標籤用的是 **8x8 選單字模**，
而它的解碼器認得 `01`/`02`、把 `03` 讀成原版的延遲控制碼。

後果：

- 選單文字必須留在第 0–2 頁。charsetgen 因此優先配置選單用字。
- 道具、技能、怪物名**不能**中文化：8x8 的中文不能看。
- 取名畫面顯示**日文**名字、對白代換**中文**名字，用的是同一組位元組——
  做法是把每個中文字放進「它對應的假名原本佔的槽位」（`克` 放進 `ク` 的 `0x8E`）。
  只有五個 8x8 tile 需要複製，用在兩個中文字搶同一個假名槽位的情況。

## 踩過的坑

- code cave 裡寫成 `INC $0231`（絕對定址）而不是 `INC $31`（直接頁）會當機。
  採用的規則：**指標要用「擁有它的那段程式」用的方式來推進**。
- 把一個「不帶參數」的控制碼改成「帶參數」，造成串流失步、遊戲當機。
  可用的版本是**先偷看參數**，低於門檻就落回原版處理常式，
  這樣 patch 對「從沒動過的文字」是位元組相容的。
- 一個通過自己解碼器 round-trip 的壓縮器，在內容逐位元組相同的情況下讓 ROM 開機當機。
- 字模光柵化的 `dy = -2` 把 `「` 頂端那道橫劃推出畫布，PIL 無聲丟棄——
  括號進到 ROM 時只剩一根直線，跟 `！` 分不出來。
